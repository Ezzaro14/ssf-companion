## Source

Imported from: league `Curse of the Allflame`, patch `3.29.3.1.4`

## New league refresh

```powershell
# 1. download base_items.json and mods.json into data/
# 2. import, wiping the previous rows
python manage.py import_mod_data --source data --league "<league>" --patch "<patch>" --force

# 3. regenerate the test fixtures from the new dump
python scripts/make_fixture.py

# 4. run the tests
pytest tests/test_crafting.py
```

`--force` will delete all existing `Mod` and `BaseItemType` rows first. Without it, reimporting an existing version is refused rather than silently duplicated.

## Schema notes

### The three tag roles

The easiest thing in this schema to conflate:

| Field | Holds | Used for |
|---|---|---|
| `BaseItemType.tags` | tags the base item carries — `body_armour`, `utility_flask`, `default` | matched against spawn weights to decide eligibility |
| `Mod.tags` | the mod's own descriptive tags — `life`, `attack`, `physical` | categorisation; generation-weight matching |
| `Mod.adds_tags` | tags this mod grants to the item it lands on | changes which other mods become eligible afterwards |

A mod is eligible on a base when the base's tags match a positive spawn weight on that mod.

`adds_tags` is why the importer needs a third pass: a mod can add a tag that other mods key off, so every `Mod` row must exist before any of these links can be written.

### Why `order` exists on SpawnWeight and GenerationWeight

Spawn weights are an **ordered list** and the first matching tag decides. The order carries the meaning, not the values — which is why the column exists and why losing it during a bulk import would be silently catastrophic rather than obviously broken.

Two patterns appear in the data and both must be handled:

**Block-list** — `FlaskIncreasedRecoveryOnLowLife1` ("Prudent"):

```
utility_flask    0
mana_flask       0
default        600
```

locked on utility and mana flasks, available at weight 600 everywhere else. Reversing this list inverts the mod's meaning entirely.

**Allow-list** — `LifeLeechPermyriadSuffix1` ("of the Remora"):

```
ring          1000
amulet        1000
gloves        1000
quiver        1000
default          0
```

Available on those four only, blocked everywhere else.

The first-match-wins rule is documented on the poewiki `Modifier` page, and the ordinal significance of `spawn_weights` and `generation_weights` is noted in the wiki's `Template:Mod/doc`.

### Groups

A mod's group determines what it blocks: two mods sharing a group cannot coexist on one item.
`IncreasedLife3` and `IncreasedLife4` ("Stalwart" and "Stout") share a group — adjacent tiers of the same mod

### Skipped base items

`import_base_items` skips roughly 500 of the 5,461 entries, on two rules:

- `release_state` is not `released` — unreleased or legacy content
- the entry has no name — internal placeholder rows

### Generation type

Stored as the dump's string form: `prefix`, `suffix`, `unique`, and others.

The wiki's canonical form is numeric and its labels are its own invention rather than the game's — the wiki's "Intrinsic" is the dump's `unique`, and its "Delve" is `delve_area`.

## Test fixtures

`tests/fixtures/repoe/` holds a trimmed subset — 6 mods, 2 base items — so CI imports in under a second rather than 18. Generated by `scripts/make_fixture.py` and never hand-edited; hand-copying is how transcription errors get permanently baked into a test suite.

Selected for coverage of code paths rather than for realism:

| Entry | Covers |
|---|---|
| `LifeLeechPermyriadSuffix1` | suffix; allow-list weights; 7 generation weights; `adds_tags` |
| `IncreasedLife3` / `IncreasedLife4` | prefix; non-trivial required level; two tiers sharing a group |
| `FlaskIncreasedRecoveryOnLowLife1` | block-list ordering |
| `FlaskDispellsChill1` | single spawn weight |
| `MapMtxRowBoatEnabled` | no group — exercises the fallback. Not a real mod; a microtransaction flag. |
| Granite Flask | a `utility_flask` base for the flask mods |
| Glorious Plate | tag canary — five tags, catches many-to-many link failures |

`MapMtxRowBoatEnabled` looks like noise in the fixture and is there deliberately: it is the only convenient entry with no group at all.
